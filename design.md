# ShopShere Frontend — Design and File Reference

## 1. Project purpose

ShopShere is a React single-page storefront built with Vite. It provides a home page, category and product browsing, product details, registration/sign-in, profile, wishlist, and shopping-cart views. It is a frontend client: product/category/account/cart data is obtained from a separate backend through HTTP requests; this repository does not contain backend or database implementation.

The implementation uses React function components and hooks, React Router for client-side routes, a small service layer for backend calls, React Context for current-user state, and Tailwind CSS utility classes for most presentation.

## 2. Design approach and shared conventions

- **Page/component separation:** `src/pages/` contains route-level screens; `src/components/` contains UI shared or embedded by screens. `App.jsx` composes the shared shell and maps paths to screens.
- **Service boundary:** components call functions from `src/services/` rather than constructing all HTTP requests inline. `api.js` is the shared authenticated request helper for auth, cart, and wishlist operations. Product and category reads use their own `fetch` wrappers.
- **Local UI state:** `useState` stores form fields, fetched data, loading/error feedback, and transient action state. This is not a global data cache: pages fetch data when mounted and own their local copies.
- **Shared identity state:** `AuthProvider` loads the current user once on application startup and exposes `user`, `loading`, `setUser`, and `logout` through `useAuth()`.
- **Derived data:** `useMemo` is used in the product browser to build category options and filtered/sorted results. Values such as cart totals are calculated from the server response when the response omits aggregate values.
- **Async lifecycle handling:** fetch-driven components show loading/error/empty states. Some components use a cancellation or mounted flag to avoid applying results after unmount. Actions generally disable controls while a request is in progress.
- **Styling:** Tailwind CSS v4 is loaded through `src/index.css` and Vite's Tailwind plugin. Most component styling is expressed in JSX class names; `App.css` is not imported by the current application.
- **Backend paths:** the browser requests `/api/...` and `/backend/...`; Vite proxies both prefixes to `http://localhost:8080` during development and strips the prefix. Production proxying must be provided by the deployment environment; the Vite dev-server proxy is not a production backend configuration.

### Shared components (`src/components/`)

| File | What it does / why it exists | Implementation notes and logic |
|---|---|---|
| `src/components/Navbar.jsx` | Persistent top navigation, shopping/search icons, and identity-dependent links. | Reads location/navigation from React Router and user/loading state from `useAuth()`. | `src/components/ProductGrid.jsx` | Shows the home page's trending products. | Fetches products once on mount, retains records where both `active` and `trending` are exactly `true`, and renders a `ProductCard` per product. Includes loading, error, empty states, and a link to all products. |
| `src/components/ProductCard.jsx` | Reusable catalogue/trending/wishlist-style product card with product link, stock label, wishlist toggle, and add-to-cart action. | Receives a `product` prop. If a token is detected, it fetches wishlist data and checks whether any entry's nested `product.id` matches this product ID. Wishlist clicks call add/remove service methods; cart clicks add quantity `1`. Unauthenticated or unauthorized actions navigate to login. `getImageUrl` resolves the image URL. |

### Pages (`src/pages/`)

| File | What it does / why it exists | Implementation notes and logic |
|---|---|---|
| `src/pages/Products.jsx` | Catalogue page with free-text search, category filter, and sorting. | Fetches active products at mount. Builds unique category names with `Set`; `useMemo` derives filtered results. Search matches lowercased product name or brand; category filtering uses exact equality; sorting uses numeric price comparators or `localeCompare` for names. Category selection is mirrored into the URL query string so category links can be shared/bookmarked. Router state can request focus on the search input. Renders `ProductCard` for each result. |
| `src/pages/ProductDetails.jsx` | Displays a single product and lets a signed-in user add a chosen quantity to the cart. | Reads `id` from `/products/:id`, fetches the product by ID when the route ID changes, and presents loading/not-found states. Quantity is parsed with `Number` and must be an integer of at least 1 before submission. Stock quantity controls the stock label and unavailable state; the backend remains responsible for authoritative stock validation. The cart request uses `addCartItem`. The heart-shaped wishlist button is currently presentational and has no click handler. |
| `src/pages/Login.jsx` | Captures email/password, authenticates, loads the current-user record, updates shared auth state, and navigates home. | Controlled inputs use `useState`; `handleSubmit` prevents browser submission, manages loading/error state, calls `login()` followed by `getCurrentUser()`, then calls context `setUser`. On success, replaces the route with `/home`. |
| `src/pages/Register.jsx` | Captures name/email/password and creates an account. | Controlled fields and native required/type/length constraints provide basic browser validation. `handleSubmit` calls `register()` and navigates to `/login` with a success message in router state; errors are rendered inline. `Login.jsx` currently does not read or display that navigation-state message. |
| `src/pages/Profile.jsx` | Displays current-user name/email and signs the user out. | Reads `user`, `loading`, and `logout` from auth context. Shows loading and signed-out states; otherwise displays available profile fields. Logout clears the token via context/service and replaces the route with `/login`. |
| `src/pages/Wishlist.jsx` | Loads saved products and supports removing them. | Normalizes either a top-level array or `items`/`content` response collections; unwraps optional `entry.product` and drops entries without IDs. Removal calls `removeFromWishlist`, then filters the removed product from local state. Includes loading/error/empty UI and links to product details. |
| `src/pages/Cart.jsx` | Loads cart items, updates quantities, removes items, and displays totals. | Calls `getCart()` on mount and provides `refreshCart()` for post-mutation refresh. Quantity updates call `updateCartItem`; removals call `removeCartItem`. A single `busyItemId` prevents concurrent mutations. If aggregate totals are absent, `reduce` calculates item count and subtotal total. `formatPrice` formats INR with Indian locale and two decimals. Checkout is deliberately disabled and marked as coming soon. |

|---|---|---|

### Backend and asset services (`src/services/`)

| File | What it does / why it exists | Implementation notes and logic |
|---|---|---|
| `src/services/api.js` | Common HTTP helper for authenticated API operations. | Prefixes paths with `/api`, reads `shopshere_token` from `localStorage`, adds JSON content type when there is a body, and attaches a bearer authorization header when a token exists. Non-2xx responses are read as text; JSON `message`, `detail`, or `title` is preferred for the thrown `Error`, which also carries the HTTP `status`. `204` returns `null`; other successful response text is parsed as JSON or returns `null` when empty. |
| `src/services/AuthService.js` | Authentication-related backend calls and token storage. | `login(email,password)` posts credentials, requires a token in the response, stores it in `localStorage`, and returns response data. `register(name,email,password)` posts registration data. `getToken()` reads the same local-storage key; `logout()` removes it; `getCurrentUser()` calls `/auth/me`. |
| `src/services/ProductService.js` | Public product-list and product-detail reads. | Fetches `/api/product` and `/api/product/{id}`, throws a generic error for unsuccessful responses, and parses successful JSON. Unlike `api.js`, it does not attach an authorization header or provide parsed backend error details. |
| `src/services/CategoryService.js` | Public category-list read. | Fetches `/api/category`, throws a generic error when unsuccessful, and parses successful JSON. |
| `src/services/CartService.js` | Cart API operations. | Maps `getCart()` and `getCartItems()` to GET routes; `addCartItem(productId, quantity=1)` posts JSON; `updateCartItem(itemId,quantity)` patches JSON; `removeCartItem(itemId)` deletes. All go through `apiRequest`, so they inherit token and error handling. |
| `src/services/WishlistService.js` | Wishlist API operations. | Gets `/wishlist`, posts to `/wishlist/{productId}` to add, and deletes that route to remove; all use `apiRequest`. |
| `src/services/ImageService.js` | Normalizes product/category image locations for the browser. | Returns `/placeholder-product.png` for missing values, passes through values starting with `http`, otherwise prepends `/backend`. This is URL selection logic, not image fetching. |

## 4. Algorithms and patterns actually used

This application is primarily a UI and API-integration frontend; it does not implement a complex domain algorithm. The concrete data-processing logic is:

1. **Unique category extraction:** `Products.jsx` maps product categories and passes the values through `Set` to produce unique select options, preceded by `All`.
2. **Catalogue filtering:** `Products.jsx` copies the source array, then conditionally applies array `filter` passes for case-insensitive substring matching on name/brand and exact category equality.
3. **Catalogue sorting:** the filtered copy is sorted with comparators: `a.price - b.price`, `b.price - a.price`, or `a.name.localeCompare(b.name)`. Copying before sorting avoids mutating the original `products` state array.
4. **Concurrent independent page reads:** `Categories.jsx` uses `Promise.allSettled` so category and product requests can both settle independently; successful data is still usable if the other call fails.
5. **Cart aggregate fallback:** `Cart.jsx` uses `reduce` to sum quantities and item subtotals only when the server has not provided `totalItems` or `totalAmount`.
6. **Wishlist membership / normalization:** `ProductCard.jsx` checks matching IDs with `some`; `Wishlist.jsx` maps/unpacks response entries and filters invalid product records.
7. **Request state patterns:** local loading/error flags represent asynchronous lifecycle; cancellation flags guard selected effects from state updates after unmount. These are UI correctness patterns, not a shared query cache.

## 5. Current limitations and integration notes

- `AuthService.js` stores and `api.js` reads the token in `localStorage`, while `ProductCard.jsx` and `ProductDetails.jsx` check `sessionStorage` before cart/wishlist actions. These are different storage areas, so the UI guard can disagree with the API helper about whether a user is signed in. This documentation records the current code behavior; it does not change it.
- `ProductDetails.jsx` shows a wishlist heart without wiring it to `WishlistService`; wishlist add/remove currently works from `ProductCard` and removal from the wishlist page.
- `Cart.jsx` has no checkout implementation; the checkout button is disabled.
- Registration navigates with a success message, but login currently does not render that message.
- `App.css`, `src/assets/react.svg`, `src/assets/vite.svg`, and `public/icons.svg` look like unreferenced starter assets/styles based on source-reference searches. The favicon is referenced but still uses Vite artwork.
- The current README is the Vite template, and no dedicated test script is defined in `package.json`.
